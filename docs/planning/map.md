# skillassert.com: wayfinder map

Label: wayfinder:map · Charted: 2026-10-29 · Tracker: local markdown (this folder)

## Destination

Confirmed 2026-10-29 (round 1, Q1). An approved v1 design document and a phased build plan for skillassert.com, with
the stack chosen, the data model fixed, and a learning syllabus mapped to each phase. v1 = public catalog by
category and topic, quiz player with tiers and optional timer, results with explanations for missed questions,
bookmarks and flags, personal notes, Google + email sign-in, one anonymous trial quiz, an admin review panel, and an
LLM pipeline that fills the question bank ahead of time. Building starts only after the design is approved, phase by
phase in later sessions.

**Destination reached 2026-10-29.** design.md approved, plan.md and plans/phase-0 approved. The map stays as the
index of decisions; the only open ticket is 05 (prototype, before Phase 2). New questions during a phase become new
tickets here; phase work itself is tracked in plans/.

## Notes

**Domain.** Visitors pick a category and topic, take a multiple-choice quiz at a chosen tier, with or without a
timer, and afterwards see explanations for what they missed. While answering they can flag a question as wrong or
bookmark it. Signed-in users keep bookmarks, flags, attempts and a personal notes area. One quiz is free without an
account. Content is generated by an LLM ahead of time into a question bank and reviewed by an admin before it goes
live. Future: premium tier, user-posted quizzes, and domains beyond IT such as History and Finance.

**Who.** Solo developer, experienced with Angular and Nx, wants to learn
backend and infra concepts by doing, and modern Angular best practices along the way.

**Standing preferences.**
- Learning is a deliverable: every phase and every resolved ticket ends with a "Read first" list, official docs
  first, at most 3 links per concept.
- "Scalable" means easy to add features through clean module boundaries, not load engineering (Q1).
- Cost: free tiers first, ceiling EUR 20/month all-in (Q10).
- Plan, don't do: no product code, scaffolding or dependency installs until the design document is approved.
- A decision lives in its ticket; this map only gists and links.

**Standing decisions (round 1, 2026-10-29; detail in grilling-log.md).**
- Backend split by seam (Q2): learner-facing reads/writes through a BaaS; the content pipeline (LLM generation, admin bulk ops) is an own NestJS service from day one; own API on a VPS is a later learning phase, not a rewrite.
- Backend language: TypeScript with NestJS (Q3).
- Content model: question bank per topic and tier; an attempt samples N approved questions, N = 10 default (Q4); curated fixed sets later.
- Questions are single-choice or multi-select by kind; all-or-nothing scoring per question (Q5); learner picks the format at quiz start (Q5 note).
- Content gate: generated questions are drafts until an admin approves; admin triggers generation with filters; flags route questions back to review (Q6).
- Anonymous trial enforced softly; trial data carries over on sign-up (Q7).
- Premium reserved in the model only: author and visibility on quizzes and questions; no payments or authoring UI in v1 (Q8).
- Launch content: English, IT, five topics x three tiers (Novice, Intermediate, Senior), ~20 approved questions per topic-tier (Q9).
- Angular Material + CDK (Q11).

**Standing decisions (round 2, 2026-10-29).**
- Nx monorepo in one public GitHub repo: apps/web, apps/api, libs/shared, feature-sliced Angular libs (Q12).
- Modern Angular baseline: standalone, signals, OnPush, zoneless, lazy routes, strict TS; signal services by default,
  NgRx SignalStore only for the quiz player (Q13).
- Six modules with hard boundaries on both sides: Catalog, Question Bank, Quiz Play, Learner, Identity, Admin (Q14).
- Admin is a lazy /admin area in the same app behind a role guard (Q15).
- One category tree of any depth; questions attach to leaves (topics) (Q16).
- Quiz settings at start: topic, tier, format (single, multi, mixed; mixed default), timed or not (Q17 + follow-up).
- Question states Draft, Approved, Rejected; flags queue a question for review, three distinct flags pull it (Q18).
- Generation form: topic, tier, kind, count, optional focus; background batch; stronger-model verify pass (Q19).
- Timer per quiz, 60/90/120 s per question by tier, auto-submit; score correct/total; no pass mark (Q21).
- Markdown notes with title, optional link to a question or topic, search (Q22).
- "Read first" lists per phase: official docs, one deep-dive, max three links, one optional course (Q23).
- skillassert.com is the user's, on Porkbun (Q24). Vitest, Playwright for a few flows, GitHub Actions on PRs (Q25).

**Standing decisions (round 3, 2026-10-29).**
- Stack: Supabase Free (EU) for Postgres, Auth, RLS, Storage; NestJS in Docker behind Caddy on a small EU VPS
  (Hetzner first, OVH fallback); Angular on Cloudflare Pages with Cloudflare DNS, Porkbun stays registrar; stay on
  Supabase Free, growth exit = self-host (Q26). ADR 0001.
- Environments: local Supabase via CLI + Docker, migrations in repo, one cloud project = production, migrations
  applied from CI (Q27).
- Auth: Google, email + password with confirmation, anonymous sign-ins, manual identity linking for the upgrade;
  custom SMTP from day one (Q28; tickets 03 and 06).
- Logic placement: learner path direct to Supabase under RLS; start-quiz and submit-attempt as Postgres functions;
  NestJS owns generation, verify, import, bulk admin, with a server-only role and admin check from the token (Q29).
- Core data model as listed in Q30; stored quiz entity only with curated sets.
- Delivery: main + PRs + Conventional Commits; CI lint/test/build; on merge Pages deploy, API image to GHCR and
  pull on VPS, migrations applied (Q31).
- Ops: nightly dump to free object store, 14-day retention; daily DB-touching health job; free uptime monitor and
  error tracker (Q32; ticket 04).
- Prerender home and category pages at build time; no runtime SSR (Q33).
- Legal: privacy, terms, account deletion, cookieless analytics, no banner (Q34).
- LLM: API key per token regardless of vendor; one pipeline for launch and ongoing; vendor from research 02 (Q35;
  ticket 07).

**Standing decisions (rounds 4 and 5, 2026-10-29).**
- LLM: no API credits on ChatGPT Plus; two adapters (Anthropic, OpenAI) with a blind bake-off on the first batch;
  five questions per call, strict JSON schema, lowest reasoning effort, synchronous three in flight; caps $2 per
  batch and $10 per month plus a vendor-console limit (Q36 to Q40).
- First public slice is the learner path with offline-reviewed imported content; admin area and hosted pipeline
  follow (Q41). Launch stock 20 per topic and tier in total; formats unlock by stock (Q42). Claim-token merge for
  trials taken by returning learners (Q43).
- Builder-check calls: markdown with code blocks for question text; anonymous flags never count toward the pull;
  prerendered pages carry only the category tree; player and results may start on plain Material.

## Decisions so far

- [01 Backend and hosting landscape](issues/01-backend-hosting-landscape.md) (research, 2026-10-29): Supabase Free
  fits the relational model with pausing, SMTP and edge-function limits to design around; Firebase and the lighter
  BaaS options ruled out; LLM batch needs a VPS; Cloudflare Pages is the only free SPA host without commercial-use
  or credit traps. Full facts in research/01.
- [02 LLM generation cost and capabilities](issues/02-llm-generation-cost-and-capabilities.md) (research, 2026-10-29):
  generation costs cents to a few dollars at launch on any vendor; all have JSON-schema output and batch; Gemini free
  tier barred for EEA apps; reasoning tokens are the cost risk; ChatGPT Pro/Business plans carry API credits. Full
  facts in research/02.
- [04 Operations and hosting mechanics](issues/04-ops-and-hosting-free-tiers.md) (research, 2026-10-29): B2 for
  backups, Better Stack for uptime and heartbeats, Sentry EU for errors, Cloudflare Web Analytics with the EU
  exclusion switched off, web app on Workers static assets instead of Pages. Full facts in research/04.
- [03 Transactional email provider](issues/03-transactional-email-provider.md) (research, 2026-10-29): Mailjet free
  plan over Supabase custom SMTP, EU-only data, no card; SMTP2GO and Resend as fallbacks; Supabase caps 30 an hour
  after switching. Full facts in research/03.
- [06 Supabase anonymous upgrade](issues/06-supabase-anonymous-upgrade.md) (research, 2026-10-29): the user id
  survives both conversion paths, so trial data carries over on sign-up without a merge; conflicts with an existing
  account need an app-side merge (Q43); refresh the session after conversion. Full facts in research/06.
- [07 LLM vendor and generation pipeline](issues/07-llm-vendor-and-generation-pipeline.md) (grilling, 2026-10-29):
  two adapters with a blind bake-off, five questions per call, lowest reasoning effort, synchronous, caps $2 per
  batch and $10 a month. Detail in design.md section 11.
- [08 v1 design document approved](issues/08-v1-design-document.md) (task, 2026-10-29): design.md approved with
  eight v1 additions (magic links, product events and funnel, question stats, a11y and dark mode, free navigation,
  missed and bookmark quiz sources, topic progress, data export) and five items reserved for v1.1.
- [09 Phased build plan](issues/09-phased-build-plan.md) (task, 2026-10-29): plan.md and the Phase 0 task plan
  approved; Native execution, one phase plan at a time.
